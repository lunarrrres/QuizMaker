# Інструкції для ШІ-агентів

> Цей файл описує як ШІ-агент має працювати з планом QuizMaker. Читай його **першим** при кожній новій сесії.

---

## Протокол запуску нової сесії

```
1. Прочитай PROGRESS.md
2. Знайди розділ "## Поточний крок"
3. Якщо там є [IN PROGRESS] — продовж цей крок
4. Якщо поточний крок порожній — візьми перший [TODO] з "## Наступні кроки"
5. Відкрий відповідний файл phases/PHASE-X.md
6. Знайди крок за його ID (наприклад PHASE-2.3.1)
7. Виконай всі підзадачі кроку по порядку
8. Перевір критерій завершення
9. Онови PROGRESS.md
10. Переходь до наступного кроку
```

---

## Як читати файли фаз

Кожен крок у файлах фаз має таку структуру:

```markdown
### PHASE-X.Y.Z — Назва кроку

**Опис:** Що саме робиться в цьому кроці.

**Залежності:** PHASE-A.B.C, PHASE-A.B.D

**Файли:**
- `шлях/до/файлу.ts` — що створюється/змінюється

**Підзадачі:**
- [ ] Підзадача 1
- [ ] Підзадача 2

**Критерій завершення:** Як перевірити що крок виконано.

**Запис у PROGRESS.md:** `[DONE] PHASE-X.Y.Z — Назва кроку — YYYY-MM-DD`
```

---

## Правила виконання

### ✅ Обов'язково
- Виконуй підзадачі **по порядку**, не пропускай
- Перевіряй **критерій завершення** перед тим як позначити крок виконаним
- Оновлюй `PROGRESS.md` одразу після завершення кроку
- Якщо крок частково виконаний — позначай його `[IN PROGRESS]` в PROGRESS.md
- Зберігай реальні назви файлів та команди з плану

### ❌ Заборонено
- Починати наступний крок до завершення поточного
- Пропускати кроки "для прискорення"
- Змінювати архітектуру без оновлення плану
- Ігнорувати залежності між кроками

---

## Як оновлювати PROGRESS.md

Після завершення кроку:

```markdown
## Виконані кроки
[DONE] PHASE-0.1 — Ініціалізація монорепо — 2026-03-01
[DONE] PHASE-0.2 — Налаштування frontend — 2026-03-01
← додай новий рядок сюди

## Поточний крок
[IN PROGRESS] PHASE-0.3 — Налаштування backend
← або очисти якщо завершив

## Наступні кроки
- PHASE-0.4  ← видали завершені звідси
- PHASE-0.5
```

## Команди для перевірки середовища

```bash
# Перевірка що bun встановлено
bun --version

# Перевірка MongoDB (Docker)
docker ps | grep mongo

# Запуск backend
cd backend && bun run start:dev

# Запуск frontend
cd frontend && bun run dev

# Перевірка зв'язку
curl http://localhost:3000/health
```

## Якщо щось пішло не так

1. Не паніруй і не пропускай проблемний крок
2. Зафіксуй проблему коментарем у PROGRESS.md: `[BLOCKED] PHASE-X.Y.Z — причина`
3. Опиши що саме не вийшло
4. Спробуй альтернативний підхід або запитай уточнення
